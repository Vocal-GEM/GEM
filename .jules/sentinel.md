## 2025-02-27 - [Information Leakage in Error Responses]
**Vulnerability:** Raw exception strings (`str(e)`) were being returned to the client in JSON API responses across multiple files (`__init__.py`, `tts.py`, `voice_quality.py`, `voicelab_service.py`, `voice_quality_analysis.py`).
**Learning:** Returning `str(e)` directly bypasses secure exception handling and leaks internal state, API endpoints, or file paths. However, fixing this securely requires context-aware logging. Using `current_app.logger` inside non-route modules (like `voicelab_service.py`) causes fatal `RuntimeError` context crashes. Furthermore, completely removing the actual error and failing to log it creates silent bugs.
**Prevention:** Always replace raw exception strings returned to clients with generic UI-friendly messages (e.g., "Internal error occurred"). However, you must log the actual exception. In route handlers, use `current_app.logger.error`. In processing modules or services, strictly use the standard Python `logging` module (`logger = logging.getLogger(__name__)`) to ensure the errors are logged without requiring a Flask request context.

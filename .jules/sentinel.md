## 2025-02-28 - [Bypassed Input Sanitization via Variable Overwriting]
**Vulnerability:** A Stored XSS vulnerability in `submit_success_story` (`backend/app/routes/community.py`) where `title` and `story` fields were sanitized, but the sanitized variables were subsequently overwritten by raw `data.get()` calls before being saved to the database.
**Learning:** This likely occurred due to a bad Git merge or copy-paste error that duplicated the input extraction logic *after* the sanitization logic. It highlights that having a sanitization function call is not enough; the data flow from the sanitization to the database insertion must be unbroken.
**Prevention:** Perform input extraction (`data.get()`) exactly once at the top of the route handler. Immediately sanitize the extracted values and store them in distinctly named variables (e.g., `clean_title`, `clean_story`). Use these distinct variables exclusively for all subsequent logic and database insertion to prevent accidental reassignment from the raw request payload.

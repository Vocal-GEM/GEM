## 2024-07-24 - Avoiding getBoundingClientRect layout thrashing in Canvas Render Loops
**Learning:** Calling `getBoundingClientRect()` inside a high-frequency animation loop (e.g. `requestAnimationFrame` or equivalent) forces the browser to synchronously recalculate layout on every frame. In the `PitchOrb` visualization, this was causing severe layout thrashing. Furthermore, re-assigning `canvas.width` and `canvas.height` on every frame to identical values forces the browser to needlessly discard and reallocate the canvas pixel buffer and resets 2D context state.
**Action:** Use `ResizeObserver` to observe the canvas container and update cached dimensions asynchronously. Only update `canvas.width` and `canvas.height` (and re-apply scaling like `ctx.scale`) when the dimensions actually change. Ensure that explicit `ctx.clearRect()` calls are used to clear the canvas on every frame since the implicit clear from dimension re-assignment is removed.

## 2024-11-20 - Centralized renderCoordinator requires single subscription
**Learning:** When migrating from a single-shot `requestAnimationFrame(loop)` pattern to a pub/sub pattern like `renderCoordinator.subscribe(id, loop)`, the subscription MUST be placed outside of the `loop` callback. A single `subscribe()` establishes a persistent listener. Placing it inside the loop causes recursive self-subscriptions every frame, leading to fatal memory leaks and CPU crashes.
**Action:** Always refactor the loop architecture to extract the `subscribe` call to the initializer (e.g., at the end of the `start` method or in a `useEffect` initialization) and only perform data processing inside the actual callback. Furthermore, ensure the corresponding test mocks accurately reflect any constants (like `PRIORITY`) accessed from the module to prevent test suite crashes.
